# PantryFlow 下週封閉 Pilot 範圍

定案日期：2026-08-23  
執行週期：2026-08-24～2026-08-30  
狀態：**內部整合中，不可現場使用**

本文件取代先前「Excel 商品匯入、寄庫與基本匯出暫停／列為下一輪」的排程結論。它不取代真實 Supabase、不可覆蓋、RLS、私有 Storage、正式 OCR 與跨裝置驗收要求。

## 封閉 Pilot 必含範圍

### P0-A：登入與門市隔離

- Owner、ADMIN、主管與後勤使用 Email＋密碼；本次不做 Google／Apple 登入。
- 員工由主管建立獨立身份，依商家設定使用「門市＋姓名／暱稱＋6 位 PIN」或「門市＋員工編號＋6 位 PIN」。
- 每位員工保有獨立 `auth.users`、profile、organization／store membership、session 與 audit trail；禁止共用帳號、Email 自助註冊、自製 JWT。
- PIN 安全雜湊；連錯 5 次鎖 15 分鐘；主管可重設與停用。
- RLS 同時驗證 Organization、Store、active membership 與角色；不得只靠前端隱藏按鈕。

### P0-B：固定模板 Excel 商品建檔

- 可下載 PantryFlow 固定欄位 Excel 模板。
- 第一版欄位：商品名稱、商品編碼、分類、基本盤點單位、採購單位、換算率、供應商、啟用狀態。
- 匯入先解析與預覽，逐列顯示欄位／格式錯誤；未確認前不得寫入。
- 重複商品至少依 Organization 內商品編碼與標準化名稱提示，使用者明確選擇略過或更新允許欄位；不得靜默覆蓋。
- 成功列以 transaction／受控 RPC 寫入正式 Supabase catalog；錯誤列不得產生半套資料。
- 本次不支援任意第三方 Excel 格式。

### P0-C：區域與商品拖移設定

- ADMIN／獲准主管可建立、改名、啟用／停用與排序儲物區。
- 拖移只做：儲物區排序；商品在儲物區間加入、移動、移除與排序。
- 桌機為主要設定介面；手機保留基本加入／移動／移除操作，不要求複雜拖曳。
- 每次排序與關聯更新寫入正式 Supabase；停用與移除關聯不得刪除盤點歷史。

### P0-D：真實盤點

- 手機盲盤不顯示 baseline；支援 0、空白、小數與自動保存。
- baseline 順序：最近一次已核准 CLOSED 盤點 → ERP 期初庫存 → ADMIN 正式期初盤點；均無資料時阻止開始並要求建立期初盤點。
- 同商品可跨區域盤點，後勤加總但保留每區首次 entry、操作者與時間。
- ADMIN／店長可建立與指派任務、查看進度、處理差異；首次盤點不可覆蓋。

### P0-E：真實進貨

- 手機多張貨單寫入私有 Storage，排入背景 OCR 後可立即離開。
- 每日進貨工作台可依門市、實際收貨日、供應商與狀態查詢；原始 batch、原圖與每次 OCR run 永久分開保存。
- 核對資料分開保存 AI 原值、人工修正、商品編碼、未稅、稅額、含稅與正式收貨。
- ERP 只保留「待 ERP 驗收／已驗收」手動狀態與提醒，不做 ERP 串接。

### P0-F：寄庫

- 正式資料至少包含供應商、寄庫商品、採購／寄庫數量、已領用數量、可用餘額、領用日期、操作者與低庫存門檻／提醒。
- 寄庫庫存與店內實體庫存使用不同 ledger／balance，不可直接混入盤點 baseline 或店內現存量。
- 採購入寄庫與領用皆為 append-only transaction；更正另建反向／修正事件，不覆蓋原交易。
- 本次不做自動叫貨或供應商系統串接。

### P0-G：基本彙整與匯出

- 可回查每日進貨工作台與原始收據。
- 進貨彙整包含明細、供應商、未稅／稅額／含稅、核對與 ERP 手動狀態。
- 盤點彙整包含任務、進度、差異、原因、操作者與時間。
- 可列印／匯出盤點表，並匯出進貨明細與盤點差異明細。
- 匯出由正式 Supabase 資料重新產生，不改寫原始紀錄；本次不做成本財報。

## 相依順序與 Release Gate

`P0-A → P0-B → P0-C → P0-D → P0-E → P0-F → P0-G`

這是風險與交付優先順序，不代表後項可用假資料先展示。任何 P0 僅在 schema／RLS、正式 UI、正向與越權測試、跨裝置證據全部通過後才能標示完成。時間不足時，從序列尾端標示「未通過／不可使用」，不得以 mock、seed、placeholder、localStorage 或假成功訊息補齊。

| 08-25（二） | P0-B 固定模板商品匯入 | 可下載模板；預覽、逐列錯誤、重複策略；正式 catalog transaction 與回查 | 不以手動 seed 代替成功匯入 |
| 08-26（三） | P0-C 區域與商品設定 | 桌機排序與跨區加入／移動／移除；手機基本操作；重載後順序一致 | 未完成拖移時基本按鈕操作仍須真實寫入，但整項標未通過 |
| 08-27（四） | P0-D 盤點垂直流程 | 正式 baseline gate、盲盤、0／空白／小數、多區、不可覆蓋 entry、跨裝置差異 | baseline 或 RLS 未過即禁止盤點入口 |
| 08-28（五） | P0-E 進貨垂直流程 | 多圖上傳即離開、背景 OCR、每日工作台、原圖／run／修正／稅額／正式收貨 | OCR 或私有 Storage 未過即標未通過 |

每日結束必須提交並推送同一分支、更新 PR #7 與 `CURRENT_PRODUCT_STATE.md`；不得合併 `main`。

## 明確排除

- Google／Apple 登入。
- 任意格式 Excel 自動辨識。
- ERP API／檔案自動串接與成本財報。
- 自動叫貨與供應商系統串接。
- 超出區域排序、商品跨區加入／移動／移除／排序以外的複雜拖曳。
