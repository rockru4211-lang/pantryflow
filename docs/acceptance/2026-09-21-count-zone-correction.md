# 序｜盤點儲物區更正

使用者在兩張卡片定案發布後提出「假設放錯儲物區」，接受由既有「修改」入口更改儲物區，並要求「好 更新」。

## 定案行為

- 未分類卡仍可用「＋儲物區」歸區；已歸區卡不額外顯示區域名稱、標籤或移動按鈕。
- 使用卡片右上角「修改」內的「更改儲物區」選擇正確區域。
- 員工可更正儲物區；品名、規格、單位與單價仍限原有主管／行政權限。
- 移動前先保存數量與備註，成功後重新讀取；保留 0、空白、備註、經手人、單位與盤點狀態，下次沿用新配置。
- 不將移動與尚未儲存的品項資料混成兩筆不確定的更新；回應逾時或讀取失敗時先確認共同進度再恢復盤點。
- 限正在盤點且來源／目標區尚未完成的品項；完成紀錄及歷史盤點保持原樣。相同品項已存在於目標區時拒絕重複加入，不自動合併數量。

## 驗證與發布

本次延續完整應用程式與原 Cloudflare 網址，不建立預覽。資料測試使用隔離回滾 fixture，不修改商家真實資料作測試。

- 正式 Supabase 已套用 `count_move_misassigned_zone`，版本 `20260921045300`（原始碼 migration `20260921044739`）。新 fixture 在套用前／後皆通過，包含 0／空白／備註、CAS、重試、門市／角色、完成與歷史保護及下次配置。
- 修改只延伸既有 private helper 的動作分派與來源限制，未更動公開函式簽章或資料欄位。套用後安全檢查與原先相同。
- 236 項程式測試、TypeScript、正式建置與來源契約通過。ESLint 零錯誤，保留既有匯入頁的一項 hooks 警告。
- 合併前執行完整乾淨資料庫 CI，發布後精確核對正式 SHA 與所有連結資產；結果同步 Notion 開發計畫。
- 未進行 iPad 真機操作驗收。
