# 百花猿：雙向調撥登記

## 使用者定案

現場只選「一店 BeApe → 二店 Gras」或「二店 Gras → 一店 BeApe」，不再選調入／調出，不需要切換登入門市。登入門市代表登記人的作業範圍，不等於實際轉出門市。

## 本次修改

- 兩個可鍵盤操作的單選方向；新登記不預選方向。
- 同一筆 movement 保存明確 from/to，created_by 與 CREATE event 的門市仍保留實際登記人與登入門市。
- 選品項依轉出門市的有效盤點品項；換方向清除舊品項、數量、單位，保留選填備註。
- 保留原有重試 request ID 防重複、行政建檔與歷史讀取，不新增另一筆收貨端紀錄，不改已完成盤點／進貨／庫存。
- 同組織、有效 BeApe／Gras 且登入門市為其中一方；不新增任何跨店人員權限。來源商品額外只讀取 id、品名、單位、可用狀態，不暴露來源成本或貨單。
- 舊前端省略 from_store_id 的調出登記仍相容；明確傳入空來源則拒絕。舊草稿保留原本調出方向。
- 前端檢查 transfer_catalogs 能力欄位；後端尚未就緒時不允許送出，避免只有 UI 更新而方向錯記。

## 驗證狀態

本次本機已通過 8 項方向／草稿／品項範圍單元測試，以及調撥元件與 helper 的 TypeScript 語法轉譯檢查。完整 typecheck、lint、build、全套測試與隔離資料庫回歸仍需執行，語法檢查不等於完整驗證。

## 發布限制：尚未上線

本次對正式 Supabase 的套用被工具安全檢查攔下；沒有取得套用成功結果。此變更只存放於修正分支／草稿 PR，不合併 beape、不觸發正式部署。正式網址、既有資料與已設定 PIN 不變。

後續須經允許的資料庫更新流程，先確認正式資料庫的目前函式版本及 migration 狀態，再套用經測試的 migration。隔離交易回滾測試通過、前端檢查通過後，才可發布到既有 beape-ops 並驗證實際供應的 commit 與資源。不可透過其他工具繞過本次攔截。
