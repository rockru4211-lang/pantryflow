# 行政卡片功能核對與修正（2026-09-21）

本輪以獨立餐廳 `SINGLE_RESTAURANT` 的行政 `LOGISTICS` 入口為主，核對卡片實際目的頁、返回、讀寫權限、儲存衝突及匯出內容。保留既有 shell、行政進貨表格與原貨單核對流程；沒有新建進貨重拍設計。下表記錄本輪程式修改，不代表所有功能已完成正式環境操作驗收；下列驗證紀錄為提交前結果，正式發布版本須另外核對合併提交與正式站版本。

## 庫存來源與部分盤點：仍待隔離資料庫驗證

原始碼審查指出兩類需要實證的情境：歸區後完成盤點，既有庫存的原區紀錄是否會與新區實盤重複；尚未初始化庫存時，若最新一次只有部分選品／區域盤點，是否遺漏未選區域的有效庫存。卡片歸區是盤點範圍調整，不能直接當作實物庫存移動；沒有本期盤點列也不能推定該區庫存為 0。

`docs/qa/count_move_stock_regression.sql` 已保存合成帳號、組織及門市的回歸案例，涵蓋完整／部分盤點、初始化前後、歸區更正、實物移動、實盤 0、其他品項／門市與歷史快照保留。文件狀態為「待隔離資料庫驗證」，不列為已通過的 CI gate；目前不能把預期斷言當作已重現結果。

第一版可回滾 fixture 曾在 Production 因前提斷言過嚴而中止，未走完庫存案例；已確認測試帳號沒有殘留。修正前提後的再次測試遭自動審查以本輪僅授權唯讀檢查為由拒絕，之後未重試或繞過。既有 stock API 未提供足夠的來源／歸區關係，前端無法精準區分原區殘留與合法後續進貨、移動；本輪未猜測重算、歸零或修復真實資料，也未新增全面警告或停用庫存功能。

## 正式入口點查後的追加修正

第一輪已合併 PR #51，正式版 `d63df85a566c9a30a81191bd1ba2c5429cba5a66` 的版本與 12 個相依資產驗證通過。瀏覽器以現有免登入體驗的行政身分確認了盤點報表、廢棄歷史、即期立即處理及重複導航；進貨入口另暴露出彙總失敗會阻擋整個貨單讀取的問題，因此追加修正：

- 貨單清單／單張明細與進貨彙總的讀取錯誤分離。彙總失敗仍能開啟已取得的授權貨單；清除舊表與選取並停用確認、匯出，不能把失敗顯示為 0 筆。
- 過期回應不更新現在的狀態；單張明細仍驗證門市。恢復讀取只清除彙總錯誤，保留其他操作訊息。
- 既有免登入體驗補齊進貨彙總及逐列確認介接，重用既有單張核對保存。角色、門市、OCR 版本、部分失敗與重送均維持其限制，不呼叫正式資料庫。

本次追加仍為前端與體驗資料介接修正，沒有新增 migration 或更動真實業務資料。庫存歸區／部分盤點來源疑點的待驗證狀態不變。
