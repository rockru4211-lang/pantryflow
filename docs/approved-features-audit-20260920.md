# 序：功能定案與部署核對（2026-09-20）

適用範圍：獨立餐廳、無 ERP、兩門市；9/22 上線先收斂盤點、進貨、借貸、調撥。依使用者要求不開預覽。

## 9/20 22:00 最新定案：盤點只保留四步

使用者明確要求：匯入現有表建檔 → 可編輯／移除品項 → 依儲物區輸入數量 → 完成後看明細、金額、異常。此要求取代先前匯入即自動開始盤點的行為。

- 匯入保留多檔、追加、失敗檔單獨重試與整批左滑移除；成功後直接整理品項／儲物區，按「開始盤點」才建立新盤點。
- 截圖 201 項包含 63 項停用品項；原盤點快照 140 項且沒有任何已填數量。設定僅列目前可用品項；未輸入數量的既有盤點可同步配置，不要求先完成空白盤點。數字 0 也算已輸入，已輸入的盤點保留快照與進度。
- 品項清單可搜尋、編輯品名／規格／單位／單價、單筆或批次移出／恢復。移出限定目前門市，不停用另一門市的共用品項，保留歷史。
- 儲物區可先新增，再勾選要移入的品項，一次儲存。取消勾選後還要先按「移入已選」的中間步驟。
- Excel 明確的單價欄可帶入；沒有單價顯示「待補單價」。完成頁與明細顯示金額、已知金額小計／總額、缺單價數量，Excel／CSV 匯出包含單價與金額。價格存在私有快照，只在原有管理權限明細開放，後續調价不改歷史估值。
- 數量變動與缺單價可直接篩選待確認；數量差異不直接標成損耗。
- 內場 6 筆同代碼失敗根因為全形／半形括號。後端以 NFKC 對齊前端名稱正規化，真正不同品項仍拒絕共用代碼；原失敗檔需由使用者重試。

Migration `20260920142750_four_step_count_setup_and_values` 已套用正式 Supabase。新增可回滾 SQL fixture 驗證兩門市、同請求重送、未登入／外店拒絕、空白快照更新、零值鎖定、已盤資料保護、金額與缺單價、歷史估值不變；原始使用者資料未作寫入測試。正式前端版本以本次 PR 與 Cloudflare 部署 SHA 核對。

## 9/20 21:35 實測阻礙：追加 Excel 建檔失敗

正式資料庫查證：吧台 28 筆、酒類 27 筆回傳 `PILOT_HISTORY_IS_APPEND_ONLY`；酒類另 3 筆已有來源紀錄。這 58 個品項均為先前已移除來源的停用品項，沒有其他有效匯入或其他門市區域使用。不是檔案選取失敗，也沒有證據顯示與 Gemini 額度相關。

修正 migration `20260920134639_inventory_import_opening_maintenance` 已套用正式 Supabase：匯入在既有授權檢查之後，僅於期初資料處理區塊啟用既有維護模式，成功即還原，失敗由每列交易回滾；不移除歷史保護。重新匯入已移除來源時，只有沒有其他有效來源及其他門市區域使用的停用品項才恢復；其殘留 FILE_IMPORT 期初不與已移除資料重複累加。單純手動停用、其他門市使用者不會被自動啟用。

新增 SQL 執行回歸測試，使用臨時建立的獨立組織／兩門市與帳號，整個交易回滾。已在正式 schema 套用前、後通過：多份期初累加、同來源重試不重複加量、舊移除資料重匯入、保留盤點快照、手動停用與他店保護、未授權及未登入拒絕、維護旗標不外洩、直接更新歷史仍拒絕。沒有用使用者原始資料做寫入測試。

使用者原始兩份檔案仍需按「只重試失敗檔案」觸發重新建檔；未代替使用者重放原始資料。另查到內場舊批次尚有 6 筆 `PRODUCT_CODE_ALREADY_USED_BY_ANOTHER_ITEM`，不把先前畫面 141 項當作全部匯入成功；這屬另一組品項代碼衝突，未以放寬重複代碼規則掩蓋。

## 9/20 21:13 後追加定案：多檔匯入與減少操作

使用者實測 Excel 可匯入 141 項，但成功頁無追加入口，選檔也只取第一份。新要求優先於原先「改用新檔案需確認」測試：追加不刪除既有資料，取消該確認框。

- 選一次可加入多份 Excel／CSV／PDF／照片，依序處理；成功頁始終保留追加入口，匯入後可直接開始盤點。
- 每份保留獨立來源及整批左滑移除；移除仍有單次門市／檔名確認，共用品項與歷史保護沿用既有 RPC。
- 失敗不阻擋其他檔案；明確操作「只重試失敗檔案」，成功檔不重新辨識。同次頁面重複選取內容相同的成功檔案會略過。
- 不再顯示重複的成功／恢復進度提示、小提示卡與辨識方式；主操作維持開始盤點／追加檔案，有例外才顯示處理入口。
- 直接回呼開啟盤點，移除隱藏按鈕及 MutationObserver 的間接操作；門市切換以 storeId 重新掛載，寫入與移除仍限定目前門市。
- 測試涵蓋兩份實際產生的 Excel（同工作表、同列號）、失敗後繼續／只重試失敗、同名不同內容，以及按檔案更新或移除不影響另一份。

此修正不代表原始 PDF 已驗收，也未完成四大作業所有現場操作驗收；不開預覽，不呼叫正式 OCR 或改動使用者資料作為測試。

## 核對依據與結論

目前不能判定「已定案功能全部部署完整」。本次直接依據使用者附上的三頁定案圖，以及 9/15 的 `xu-ux-audit.html` 檢查文件。尚未取得名為「序 功能調整」的完整原對話，因此舊檢查文件只作補充比對，不能代替其後全部定案，也不把不同於舊圖的地方一律改回舊版。

修正前 Cloudflare 正式站的應用程式資產對應 main `d3c4ff52f25e30935c4b0ada8d1e63c5e6e7de10`。PR #40 確實部署，但將左滑入口改成直接按鈕，沒有忠實保留最新定案操作。這是實作偏差，不能只歸因於快取。
