# 百花猿：寄庫與保留貨定案

本次使用者「定案更新」沿用 2026-09-25 最後示意：庫存管理新增「寄庫」「保留貨」分頁，排在總表、差異核對、庫存金額之後。後兩頁不顯示頂部統計卡，保留品項內提醒。正式來源仍為 beape 分支與 beape-ops Worker。

- 寄庫：按目前門市、品項、供應商、單位管理已購入外部庫存；各批次保留原始數量、餘量、效期與原採購單據參考。低於安全水位、批次到期前指定日數、已到期會在品項內提示，可追蹤待聯絡／已聯絡／已下訂／補購完成。
- 保留貨：按品項、保留對象與單位記錄現場待取數量，保留原始、已取與未取數量。帳款與發票不在此處處理。
- 新增紀錄、批次不再次增加現場庫存，也不產生採購金額。寄庫領回增加目前門市現貨，保留貨取走減少門市現貨。兩者保留日期、批次、經手人、登入登記人與備註；不改寫月盤／封存金額／原進貨紀錄。
- 餘量不依月份清空；月份只篩選展開的歷史紀錄。領取優先顯示較早到期批次，過期批次不可領取，超過批次餘量或現貨不足時整筆拒絕。
- 目前管理入口與資料僅開放有效行政／後勤及老闆身分。主管／員工的盤點畫面、進貨新品項審核、公司抽盤派發流程沒有在本次更動。安全水位及效期提醒在此分頁顯示，沒有另外發送電子郵件或外部推播。
- 以 private tables、RLS 預設拒絕、私有 definer API 加 public invoker wrapper 實作，前端沒有直接表格權限。每次操作檢查有效帳號、門市、角色與工作階段。store transaction lock、revision 與 request UUID 防止多人覆寫、重複領取及重試重扣。
- 前景每 5 秒補讀，編輯時暫停替換。衝突保留輸入，重新讀取後可再核對。網路中斷且結果不明時保留同一請求重試，避免重複登記。切換分頁及離開頁面有未儲存保護。

## 驗證

- 正式 schema 上獨立 UUID fixtures + rollback：角色拒絕、跨門市拒絕、停用帳號拒絕、原始入帳不重複、兩種領取庫存方向、同請求重試、舊 revision 拒絕、超量／過期拒絕、設定保存、批次合計與歷史盤點不變。
- Typecheck、7 項相關 node tests、修改檔案 ESLint、source contract 與完整建置通過。
- Playwright 實際 React 元件 + 模擬 API：5 分頁、寄庫／保留貨不顯示統計卡、衝突保留輸入、網路結果不明時以相同 request UUID 重試、390px 手機頁面不溢出、無 runtime errors。
- 全專案 lint 有既有 partners-stores-workspace 同步 effect 錯誤與 19 個警告，已核對該檔原分支內容，本次沒有修改該檔。
- Supabase security advisors：新增三張 private 表的 RLS 無 policy 是刻意的拒絕直接存取；未新增公開 definer endpoint。既有其他功能的 advisory 未在本次擴大修改。
