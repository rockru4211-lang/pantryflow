## 目標

先交付可由餐廳現場實際走完的「盤點＋進貨」測試版。盤點是員工首頁唯一主要作業；進貨保留為可直接開啟的第二條測試流程。效期、廢棄、借貸、叫貨、複雜排程與多角色儀表板不進入本輪驗收。

## 盤點

1. 主管第一次只設定一次：可直接匯入現有 CSV／XLSX，或手動建立區域及品項。
2. 匯入不要求使用者先整理固定範本；缺商品編碼、單位或區域時由系統產生安全預設，重複列保留並產生唯一編碼，正式寫入前仍顯示預覽。
3. 基礎資料完成後，系統自動建立每日盤點設定並產生當日任務；畫面不得要求使用者每天建立或發布任務。
4. 員工只看當日盤點、選區域、輸入實際數量並完成；輸入自動保存，盲盤期間不顯示上次數量、差異、成本或金額。
5. 全部區域完成後才由系統整理差異；原始實盤與後續更正保持追加式紀錄。

## 進貨

1. 員工與主管都可拍攝或選擇最多 10 張貨單，指定同一貨單或不同貨單後上傳辨識。
2. 保留原圖、OCR run、AI 原值、人工修正、操作者及時間，不覆蓋證據。
3. 每個辨識品項可填實收數量與到貨狀況（相符、少送、多送、未送、送錯），另存現場確認事件。
4. 金額固定以 TWD／新台幣呈現，只作為庫存與營運資料，不宣稱會計或報稅用途。
5. ERP 是門市設定的選用輔助，不因餐廳類型強制顯示。

## 驗收範圍

- 不提供假角色切換器、iframe 或展示用假資料入口。
- 測試必須使用真實 Supabase Auth、門市 membership、RLS 與既有資料。
- GitHub `main` 仍是正式前端唯一來源；測試分支通過後才可合併並觸發 Pages。
- 2026-08-28 已在 production 存在的四筆 migration 先回補至 GitHub，這是來源對齊，不代表本決策授權新的 production schema 變更。
