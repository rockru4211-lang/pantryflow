## 同一套系統、兩種營運模式

建立商家時在既有「建立商家」步驟選擇：

1. `SINGLE_RESTAURANT`：中小餐廳／單店｜App 盤點＋匯出。
2. `CHAIN_RESTAURANT`：連鎖餐飲／多門市｜紙本謄寫＋跨店追蹤。

營運模式只套用預設功能，不建立第二套登入、前端或資料模型。日後可由 Owner／主管在「設定 → 盤點設定」調整。未啟用的功能必須完全隱藏，不得用停用按鈕或解釋文字占據第一線畫面。

## 共通完成流程

- 兩種模式都能查看與匯出盤點明細。
- 員工端匯出支援 Excel 相容 CSV、PDF／列印版面；V1 先以可重新產生的 CSV 與列印完成，PDF 可由列印另存。
- 原始盤點數量不可覆蓋；更正需追加事件並保留前後值、操作者與時間。

### 中小餐廳／單店

盤點完成 → 查看盤點明細 → 匯出或列印 → 返回首頁。

紙本謄寫、主管紙本確認及跨店追蹤預設完全隱藏。

### 連鎖餐飲／多門市

盤點完成 → 員工謄寫企業既有紙本 → 留下經手人與時間 → 主管確認／稽查 → 匯出盤點明細。

紙本是企業既有制度的條件式流程，不是 PantryFlow 對所有餐廳新增的重複作業。PantryFlow 只追蹤完成與稽查狀態，不要求把紙本內容再輸回 App。

## 角色資訊架構

### STAFF｜員工（綠）

- 執行盲盤。
- 依營運模式顯示或隱藏紙本謄寫。
- 查看、匯出本次盤點明細。

### ADMIN／SUPERVISOR｜店長／主管（橘）

- 設定盤點區域、品項、順序、單位與盲盤規則。
- 建立／發布本店盤點任務。
- 確認差異原因、查看本店總結、執行紙本與現場稽查。

### LOGISTICS／BACKOFFICE｜後勤（藍）

- 整理跨店盤點資料與缺漏。
- 分類差異、進行檢討與趨勢分析、產出報告。
- 不可覆蓋員工原始盤點，也不代替主管批准現場原因。

### OWNER｜Owner／管理者（紫）

- 查看後勤整理後的結論、重大異常、門市比較與稽核結果。
- 決定盤點政策與營運模式。
- 不承擔日常資料清理或逐筆差異整理。

後勤與 Owner 不得共用同一盤點首頁；店長／主管、後勤與 Owner 也不得只換角色色而保留相同功能。
