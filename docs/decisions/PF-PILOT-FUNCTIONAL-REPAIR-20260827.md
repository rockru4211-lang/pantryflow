# PF-PILOT-FUNCTIONAL-REPAIR-20260827

日期：2026-08-27  
狀態：開發中  
適用：正式 Pilot 的 ADMIN／SUPERVISOR、STAFF 與進貨核對者

## 問題

公開 Pages 已呈現定案畫面，但主管實測發現三個流程沒有形成正式資料閉環：盤點表只能選檔預覽、區域建立受錯誤的跨門市唯一索引阻擋、進貨 OCR 的資料庫狀態與前端狀態名稱不同。另一個已確認問題是跨分頁登出後舊頁仍顯示主管畫面，直到下一次寫入才回傳 401。

## 本輪定案

1. 登入 session 失效或收到 `SIGNED_OUT` 時，立即清除記憶體中的角色／門市狀態並返回登入頁；不得繼續顯示可操作的舊主管畫面。
2. 盤點區域名稱只在同一門市內不可重複。主管可建立、重新命名、排序、停用區域，並可加入或移除區域品項；停用不刪除歷史。
3. 盤點表支援 CSV 與 `.xlsx`。選檔後先檢查商品編碼、名稱、單位、重複列與來源位置；驗證通過後由主管再次確認才正式匯入。
4. 正式匯入先把原檔保存於 private Storage，再以單一資料庫交易建立／對應區域、商品、期初零值與區域順序。來源工作表、原列號、數量欄位與原列值一併保存，發布後不可覆蓋或刪除。
5. 盤點完成後，若品項具有匯入來源，回填版使用 `.xlsx` 並把數量寫回原工作表列號與數量欄位；缺少來源的舊資料才退回相容 CSV。
6. 進貨沿用既有多圖 private Storage、OCR queue 與不可覆蓋 run。前端正式採用資料庫狀態 `PROCESSING → READY_FOR_REVIEW／REVIEWING → COMPLETED`，OCR run 失敗另顯示 `FAILED` 並提供保留原圖後重新辨識。
7. 現場人員與主管可查看自己門市、且符合上傳者或主管條件的 OCR 結果；人工修正仍限主管／核對角色。Owner 只看完成後摘要。

## 不包含

- 不更換 OCR provider 或模型。
- 不把 OCR 結果直接當正式會計資料。
- 不刪除既有區域、盤點、照片、OCR run 或人工修正。
- 本輪先完成可上傳、辨識、查看與重試；商品 mapping 與正式收貨發布仍遵守既有 `finalize_goods_receipt` 完整核對閘門，不以假發布取代。

## 驗收

- CSV 匯入保留原列號與數量欄位；重複或缺單位不得發布。
- 同名區域可分屬不同門市；同一門市不可重複。
- 主管可重新命名、上下排序、移除品項與停用區域。
- 多張貨單原圖上傳後可看到辨識中、待核對或失敗；失敗可重新辨識。
- 任何跨分頁登出或失效 session 都回登入頁。
- 全站 Node 測試、Pages runtime smoke、production RLS／migration smoke 通過後才標示上線待驗收。
