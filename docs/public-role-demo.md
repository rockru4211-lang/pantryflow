# 免登入身分體驗

入口為同一個 Site 的 `/demo`。登入首頁提供「免登入體驗」連結。

選擇獨立餐廳或連鎖餐飲，再選員工、主管／店長、行政後勤／區主管、老闆。管理身分可另勾選商家管理權限，比較增加權限前後的功能。

## 共用與隔離

- 正式登入與示範共同使用 `AuthenticatedWorkspace` 及現有各工作元件。
- 只有完整路徑 `/demo` 或 `/demo/` 可以選到本機資料介面；查詢參數無效。
- 第一次使用即固定資料介面。往返正式入口使用整頁導覽，避免跨頁沿用錯誤介面。
- 示範不初始化 Supabase Auth、不刷新真實登入、不註冊正式操作追蹤，也不修改 RLS、RPC 或資料庫結構。
- 示範資料全為合成資料；作業與草稿放在此瀏覽器的隔離儲存區，保留七天；切換身分及重新整理仍保留。「重設範例」只清除此隔離資料。
- 未實作的 API 一律回傳 `DEMO_UNAVAILABLE`，不轉送正式 API。

## 可操作的示範

盤點輸入、完成區域與紙本；收貨欄位核對與確認；效期提醒、已使用完、廢棄與風險回報；交接、異常、公告；借貸與歸還；商品及供應商資料；範例成員的權限、代理與停用；商家與作業設定；報表查看及本機匯出。

本次補齊 Excel／CSV／文字層 PDF 確認匯入、失敗修正重試、員工示範邀請與 PIN 啟用、借貸自訂單位、缺貨連動、品項停用與分區解凍。共同使用正式元件與數量、單位、匯入驗證規則。示範邀請只在同一瀏覽器的隔離資料中有效，不建立正式帳號。

照片與掃描 PDF 的真實 OCR 需要登入；體驗版不呼叫正式辨識服務。示範匯入原檔 Blob 只保留於目前分頁，重新開啟需再選同一原檔；已確認品項、來源原文、順序與作業紀錄仍保留。邀請信、裝置授權及商家管理責任交接仍須使用正式帳號驗證。預設進貨範例不聲稱已完成新的 OCR 或寄信。

## 驗證

先執行 `npm run verify:source`、`npm run typecheck`、`npm run lint` 與 `npm run build`，再執行 `npm test`。HTML 與 CSS 測試需要已建置的 `dist`。

`tests/public-demo.test.mjs` 驗證八種身分、額外權限、跨身分共用作業、餐廳與門市隔離、重設及無網路退回路徑。正式登入的既有測試仍保留。
