# 行政網頁進貨核對調整

行政使用桌面核對貨單時，原本逐列開啟的窄版「修改品項」視窗會遮住原單與表格。本次保留原外殼及現場人員流程，將行政核對改為頁面內編輯。

- 原單與資料並排；原單可切換檔案、放大、查看 PDF 或另開原檔，也可收起來源區。
- 供應商、日期及單號在貨單上方直接修改；品名、規格、單位、數量及單價在表格輸入。商品對應與其餘欄位留在該列展開。
- 支援逐列或一次儲存全部修改；未儲存、等待重新讀取及衝突均不當作已完成核對。
- 草稿依使用者、門市、貨單及 OCR 版本隔離。背景重新讀取保留未存內容及原始比對基準；明確捨棄才使用最新資料重建。
- 總表批次確認會檢查該貨單的本機草稿，避免離開明細後誤用舊資料確認。

沿用 `receipt.edit-card` 的整列原值與商品對應比對、請求重送及既有權限，不新增 migration；完成核對仍使用既有發布流程。沒有拿真實貨單、庫存或金額做測試寫入。

驗證結果隨本次 PR 記錄；此文件描述調整範圍，不代替正式部署驗證。

提交前完整 Node 測試 316/316 通過（本次增加 20 項）；TypeScript、建置及來源契約通過。Lint 僅保留既存匯入頁 hooks 警告。實際元件測試包含背景更新、原值比對、失敗保留、依序儲存、跨店隔離、草稿恢復、缺列阻擋完成、民國日期、空白／零及計算金額與原始金額分離。
