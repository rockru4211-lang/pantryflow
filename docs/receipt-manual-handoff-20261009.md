# Manual receipt intake without waiting for OCR

The archive and receipt status now open the existing inline receipt review workbench through 建檔／核對. Source photos are visible on the right and can be hidden. Administrative users can take over queued, failed, or partially recognized receipts without creating a second receipt. Blank row creation is idempotent, permits later completion of fields, and uses the existing audited correction/save system. Ambiguous OCR and empty required fields are hints, not draft-save blockers.

Takeover preserves the latest successful OCR version and includes named partial rows unless previously ignored. When no successful extraction exists, a versioned manual-entry draft with explicit manual provenance is created; original failed runs and images remain. A private handoff record prevents enqueue and new OCR run creation. Outstanding job leases are invalidated under the dispatcher/batch locks; late commits fail the existing lease check. Content failures with no usable lines or empty structured output now stop for human handling, while provider quota/busy retries retain their existing scheduling.

Recent supplier items come from the same store's last 90 days of edited/checked receipt history. Selection fills name/specification/unit only. Prior price is dated and explicitly applied; quantity and entered price are preserved. No new AI billing, provider, or API key is configured.

Validation: isolated rollback fixture covers owner/staff/view-only and cross-store denial, takeover and row-add idempotency, stale worker commit and new run/enqueue denial, nullable draft save/retry, unchanged original image/history, successful partial extraction preservation, and archive metadata consistency. Frontend regression covers manual entry visibility, quota labels, safe item/price selection, nullable correction saves and retry preservation. Existing receivings tests, typecheck, scoped lint and production build are required. New SQL migration must be applied before the frontend deployment. Do not requeue historical failed receipts or modify real receipt content as QA.
