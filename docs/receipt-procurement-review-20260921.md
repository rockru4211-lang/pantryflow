# 行政進貨請購表式核對定案

使用者確認「左側大原單、右側一品項一列」的設計，並指定品項編碼、未稅單價、未稅金額及貨單底部另列稅額與含稅合計；同廠商集中排列，每張貨單仍分開核對。

## 本次調整

- 進入桌面核對時收起行政側欄並展寬工作區。原單預設約 48% 寬，可拖動中間分隔線或使用方向鍵調整，圖片支援縮放、拖移、多頁及 PDF。離開核對恢復既有外殼。
- 上方直接修改供應商；日期簡短顯示、按需修改。單號保留，其他原始資料收進更多資料。
- 明細一品項一列：編碼、品名、規格／備註、單位、數量、未稅單價、未稅金額。商品對應、原始小計與逐列儲存按需展開；錯誤自動展開。
- 編碼取自已對應商品，不改寫全商家編碼。修改品名／規格／單位會解除舊對應，舊編碼隨之消失；換商品儲存成功後讀取新編碼。
- 每張貨單底部提供明細未稅合計、原單稅額、試算含稅合計，另保留原單未稅及含稅合計供比較。金額不一致會提示，原單數字不因試算被覆寫。缺少數量、單價或稅額時保留未提供，不假設 0 或固定 5%。
- 總表依供應商及貨單分組；切換器同樣依供應商分組，顯示貨單日期、上傳編號及狀態。上傳編號與供應商貨單單號分開標示，真正單號保留於開啟的貨單內。
- 原圖檢視器以貨單 ID 重建，避免沿用前一張頁碼與縮放。明細元件沿用使用者／門市／貨單／辨識版本隔離的草稿；儲存期間停用切換。
- 到貨、異常、ERP 與上傳紀錄仍在核對頁下方按需展開。現場員工上傳流程、盤點定案、權限及歷史資料不變。

## 驗證與發布

本次沒有資料庫變更。沿用既有整列修正與核對 API，沒有對真實貨單或庫存寫入測試資料。
